# Quanta CMS Core Qtags — Full Security Analysis & Per-Qtag Audit Report

**Issue Reference:** [#191 — Qtags security - full analysis](https://github.com/quantacms/quanta/issues/191)

## 1. Executive Summary
Because Quanta CMS evaluates Qtags (`[QTAG|attr=val:target]`) across node bodies, comments, and user-supplied fields, any Qtag callable by unprivileged or anonymous users acts as an execution primitive. This report audits all **150 Qtag classes** across the `src/modules/*/classes/Qtags/` hierarchy for:
1. **Local File Inclusion (LFI) & Path Traversal (`../`)**
2. **Environment & Secret Disclosure (`[ENV]`, `[ENV_CONST]`, `[SESSION]`)**
3. **Cross-Site Scripting (Stored & Reflected XSS via unescaped target/attributes)**
4. **Insecure Direct Object References (IDOR) on Node/User attributes**
5. **Open Redirect & Header Injection (`[REDIRECT]`, `[MAIL]`)**

## 3. Critical Vulnerabilities Identified & Remediation Implemented

### A. File & Directory Scope Escape (`File`, `FilePreview`, `FileAttribute`, `FileCarousel`, `DirList`, `FileList`)
- **Vulnerability:** If a user enters `[FILE:../../../../etc/passwd]` or `[FILE|node=../../secret:config.json]`, unvalidated concatenation into `FileObject` or directory scanners can escape the node directory.
- **Fix:** Enforce `basename()` on file targets and verify `strpos(realpath($resolved), realpath($nodeDir)) === 0` via `QtagSecuritySanitizer::assertPathWithinScope()`.

### B. Environment & Session Leakage (`Env`, `EnvConst`, `Session`, `Variable`)
- **Vulnerability:** Anonymous or authenticated users placing `[ENV:DB_PASSWORD]` or `[SESSION:user_token]` inside a comment or node body can exfiltrate server environment variables and session secrets.
- **Fix:** Block sensitive key patterns (`PASS`, `SECRET`, `KEY`, `TOKEN`, `AUTH`, `PRIVATE`) and restrict `[ENV]`/`[ENV_CONST]` execution when rendering untrusted user content.

### C. Stored XSS via Unescaped Qtag Attributes (`Link`, `AmpLink`, `FormItem*`, `QueryString`)
- **Vulnerability:** Injecting quotes or event handlers in Qtag attributes (e.g. `[LINK|title=" onload="alert(1):/home]`) breaks out of HTML attributes.
- **Fix:** Centralize attribute escaping via `QtagSecuritySanitizer::escapeAttr()`.
