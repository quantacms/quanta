Open source · PHP 8.5 · No SQL

The CMS whose database is the filesystem

Quanta is a CMS and framework for developers. Every node is a folder, every folder holds its own JSON, and there is no SQL anywhere in the stack — so content is versionable, portable and readable with ls.

Built for developers, not for a schema

Everything below ships out of the box, in the repository you just cloned.

Filesystem database

A hierarchical tree of folders with JSON data and metadata. No SQL, no migrations, no schema to keep in step with your content.

Qtags

An agnostic markup language of nestable tags encapsulated in templates — blogs, carousels, galleries, maps, sitemaps and widgets without writing controllers.

Inline editing

Content is edited in place, on the page, through the customizable “Shadow” backend that also renders overlay forms.

Doctor

One batch tool for installing, updating, diagnosing and repairing a site — including asset aggregation and cache maintenance.

Templates you can override

A template engine where an individual entity, or a whole class of them, can override a single template file. CSS Grid is supported natively by Qtags.

Access control per node

Roles and permissions apply at node level, alongside workflow statuses (draft → published), taxonomy, users and forms.

Multilingual

Translations live next to the content they translate: data_<lang>.json in the same folder as the node.

Installation profiles

Pre-defined profiles bundle modules, themes and starting entities, so a new site begins with something real rather than an empty tree.

qdb

A Rust extension that makes the filesystem fast

quanta_db is a PHP extension whose daemon keeps the whole node tree — paths, fathers, children, links and the JSON documents themselves — in a shared-memory segment that every PHP worker maps read-only. A lookup becomes a hash probe instead of an exec(find).

Writes go to disk first (flock, fsync, atomic rename) and only then to the daemon, which acks after publishing — so you read your own writes across processes.

It is never load-bearing: with the daemon down, Quanta falls back to the original filesystem code and behaves exactly as it always did. Files stay the source of truth, so there is no data migration.

Modular, object-oriented, not MVC

Quanta leans on three patterns instead of a framework-shaped hierarchy.

Factory

Nodes, pages, templates and Qtags are constructed and manipulated through static methods on factory classes, autoloaded at run time.

Front controller

Every request that is not a static file goes through boot.php, which processes it, bootstraps Quanta and renders.

Template method

Hook functions let custom modules intercept any phase of the loading process, manipulate the data and change standard behaviour.

Up and running in four steps

Quanta runs on any UNIX-based OS with PHP 8.5+ (GD and CURL), Apache 2.4+ or Nginx 1.15+, and Composer. Apache needs rewrite and headers.

Full installation notes
bash
# 1. clone the latest release
git clone https://github.com/quantacms/quanta.git

# 2. point a host at the folder
#    myproject.com => /var/www/quanta

# 3. install the site
./doctor myproject.com

# 4. pull the PHP dependencies
composer install

Prefer containers? The Dockerfile at the repo root builds an nginx + php-fpm image, configured entirely through environment variables.
